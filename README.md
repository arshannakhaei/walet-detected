# ChainTrace — ردیابی و تحلیل جریان پول در بلاکچین

آدرس یک کیف پول را می‌دهید؛ ChainTrace تراکنش‌هایش را از APIهای عمومی بلاکچین می‌گیرد و نشان می‌دهد:

- **از چه ولت‌هایی پول آمده و به چه ولت‌هایی رفته** (و آن‌ها از کجا گرفته‌اند / به کجا داده‌اند — گراف چندلایه)
- **مسیر یک مبلغ مشخص** را مرحله به مرحله دنبال می‌کند تا به صرافی یا مقصد نهایی برسد
- **الگوهای مشکوک** (پول‌شویی، ولت‌های عبوری، تماس با آدرس‌های تحریمی/میکسر، address poisoning) با امتیاز ریسک و شواهد
- **مانیتور و هشدار** تراکنش‌های جدید در داشبورد و **ربات تلگرام**
- **سرور MCP** تا Claude مستقیماً بتواند ولت‌ها را تحلیل کند

شبکه‌ها: **Tron** (TRX, TRC20)، **Ethereum, BNB Chain, Polygon, Arbitrum, Optimism, Base, Avalanche** (کوین اصلی، توکن‌ها، تراکنش‌های داخلی)، **Bitcoin**، **Solana** (SOL, SPL).

📄 **گزارش کامل پروژه** (برنامه‌ریزی، راهنمای تصویری، معماری، تست‌ها و نقشه‌ی راه): [`docs/report.html`](docs/report.html) — در مرورگر باز کنید.

## اجرای سریع

پیش‌نیاز: **Python 3.11 یا جدیدتر** ([python.org](https://www.python.org/downloads/) — در ویندوز تیک «Add Python to PATH» را بزنید). Node.js لازم نیست؛ داشبورد از قبل ساخته شده است.

| سیستم | کار |
|---|---|
| **ویندوز** | روی `start.bat` دوبار کلیک کنید |
| **مک / لینوکس** | `./start.sh` |

بار اول کتابخانه‌ها نصب می‌شوند (چند دقیقه)، بعد وقتی سرور آماده شد مرورگر خودش روی <http://127.0.0.1:8765> باز می‌شود.
اگر پورت در دسترس نباشد، برنامه خودش پورت بعدی را انتخاب می‌کند و آدرس درست را در پنجره‌ی سیاه می‌نویسد.

### اگر صفحه باز نشد

- آدرسی را که در پنجره‌ی سیاه بعد از `ChainTrace  ->` نوشته شده باز کنید (ممکن است پورتش ۸۷۶۵ نباشد).
- خطای `ERR_EMPTY_RESPONSE` یا `WinError 10013` یعنی برنامه‌ی دیگری یا خود ویندوز (Hyper-V/WSL/Docker) پورت را گرفته؛ نسخه‌ی جدید خودش پورت دیگری انتخاب می‌کند. می‌توانید در `.env` هم پورت دلخواه بنویسید، مثلاً `PORT=18765`.
- VPN/فیلترشکن در حالت TUN یا System Proxy ممکن است ارتباط با `127.0.0.1` را خراب کند؛ آن را خاموش کنید یا localhost را از پروکسی مستثنا کنید.
- خطای `HTTP 429` یعنی سقف درخواست سرویس رایگان پر شده (TronGrid بدون کلید فقط ۱ درخواست در ثانیه؛ با VPN زودتر پر می‌شود). در صفحه‌ی **تنظیمات** کلید رایگان TronGrid و Etherscan را وارد کنید؛ بلافاصله اعمال می‌شود.
- `doctor.bat` (یا `python scripts/doctor.py`) را اجرا کنید و خروجی‌اش را بفرستید: نسخه‌ی پایتون، کتابخانه‌ها، وضعیت پورت و برنامه‌ی اشغال‌کننده، و پروکسی را نشان می‌دهد.

### حالت دمو (بدون اینترنت)

برای ارائه یا تست بدون اینترنت، در فایل `.env` بنویسید:

```
DEMO_MODE=true
```

شبکه‌ی ترون با یک سناریوی ساختگی پر می‌شود: ۱۴ قربانی به یک کلاهبردار پول می‌دهند، پول بین ۴ ولت واسط پخش می‌شود،
از یک زنجیره‌ی peel chain می‌گذرد و به یک ولت صرافی و یک آدرس تحریم‌شده‌ی OFAC می‌رسد. در صفحه‌ی اول دکمه‌های
«ولت کلاهبردار / قربانی / ولت واسط» ظاهر می‌شوند. همه‌ی بخش‌ها (گراف، ردیابی، ریسک، پرونده، ...) روی این داده کار می‌کنند.

### اجرای دستی

```bash
python -m venv .venv
.venv\Scripts\activate          # مک/لینوکس: source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

### اجرا با Docker (اختیاری)

1. [Docker Desktop](https://www.docker.com/products/docker-desktop/) را نصب و اجرا کنید (در ویندوز به WSL2 نیاز دارد).
2. روی `start-docker.bat` دوبار کلیک کنید (یا: `copy .env.example .env` و بعد `docker compose up -d --build`).
3. <http://127.0.0.1:8765> را باز کنید. برای توقف: `docker compose down`.

کلیدهای API را از صفحه‌ی تنظیمات وارد کنید؛ در `.env` ذخیره می‌شوند و بعد از restart کانتینر می‌مانند. کش و پرونده‌ها در `backend/data` می‌مانند.

> Docker سرعت را زیاد نمی‌کند: کندی از سقف درخواست APIهای رایگان بلاکچین است، نه از کامپیوتر. برای سرعت، کلیدهای رایگان TronGrid و Etherscan را در تنظیمات وارد کنید. از این نسخه، صفحه‌ی ولت جدیدترین تراکنش‌ها را در چند ثانیه نشان می‌دهد و بقیه‌ی تاریخچه در پس‌زمینه دریافت می‌شود.

## تنظیمات (`.env`)

همه اختیاری‌اند؛ بدون کلید از endpointهای رایگان عمومی استفاده می‌شود. `.env.example` را به `.env` کپی کنید.

| متغیر | کاربرد |
|---|---|
| `TRONGRID_API_KEY` | کلید رایگان [trongrid.io](https://www.trongrid.io) — بدون آن ۱ درخواست در ثانیه، با آن ~۱۵. از صفحه‌ی تنظیمات هم وارد می‌شود |
| `ETHERSCAN_API_KEY` | یک کلید رایگان [etherscan.io](https://etherscan.io/apis) برای **همه‌ی شبکه‌های EVM** (Etherscan V2). بدون آن اتریوم/پالیگان/آربیتروم/اپتیمیزم/بیس از Blockscout استفاده می‌کنند و BSC و Avalanche غیرفعال‌اند |
| `SOLANA_RPC_URL` | RPC سولانا؛ endpoint عمومی کند است، یک URL رایگان Helius/QuickNode بهتر است |
| `BITCOIN_API_URL` | Esplora API (پیش‌فرض mempool.space) |
| `COINGECKO_API_KEY` | اختیاری، برای قیمت دلاری |
| `USD_TOMAN_RATE` | نرخ دلار به تومان (دستی). خالی = نرخ زنده‌ی بازار USDT/تومان از نوبیتکس (و والکس اگر نوبیتکس جواب نداد). از صفحه‌ی تنظیمات هم وارد می‌شود |
| `MAX_TRANSFERS_PER_ADDRESS` | حداکثر انتقال دریافتی برای هر آدرس (پیش‌فرض ۲۰۰۰) |
| `HUB_THRESHOLD` | آدرس با انتقال بیشتر از این، «پرتراکنش» (معمولاً صرافی) حساب می‌شود و در گراف/ردیابی باز نمی‌شود (پیش‌فرض ۱۰۰۰) |
| `CACHE_TTL_SECONDS` | داده‌ی هر آدرس تا این مدت از کش خوانده می‌شود |
| `MONITOR_INTERVAL_SECONDS` | فاصله‌ی بررسی واچ‌لیست (۰ = خاموش) |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USERS`, `PUBLIC_URL` | ربات تلگرام (پایین را ببینید) |
| `HOST`, `PORT` | پیش‌فرض `127.0.0.1:8765`. برای دسترسی از گوشی در همان شبکه: `HOST=0.0.0.0` و آدرس IP کامپیوتر |
| `DEMO_MODE` | داده‌ی ساختگی آفلاین |

## راهنمای داشبورد

- **جستجو**: آدرس را وارد کنید؛ شبکه خودکار تشخیص داده می‌شود. برای آدرس‌های `0x...` که روی چند شبکه معتبرند، شبکه‌هایی که ولت روی آن‌ها فعالیت داشته علامت می‌خورند.
- **صفحه‌ی ولت**
  - *خلاصه*: موجودی و ارزش دلاری، اولین/آخرین فعالیت، نمودار ورودی/خروجی در طول زمان، خلاصه‌ی ریسک
  - *طرف‌حساب‌ها*: از چه کسی چقدر گرفته / به چه کسی چقدر داده، با فیلتر و مرتب‌سازی و خروجی CSV
  - *تراکنش‌ها*: همه‌ی انتقال‌ها با فیلتر؛ دکمه‌ی **ردیابی** کنار هر تراکنش
  - *گراف*: گراف چندلایه‌ی فرستنده‌ها و گیرنده‌ها؛ کلیک = جزئیات، دوبار کلیک = باز کردن لایه‌ی بعد، خروجی PNG
  - *ریسک*: امتیاز، آمار رفتاری و یافته‌ها با شواهد (آدرس‌ها و تراکنش‌ها)
  - دکمه‌ها: به‌روزرسانی، افزودن به واچ‌لیست، برچسب، افزودن به پرونده، **گزارش** (قابل چاپ / ذخیره به PDF)
- **ردیابی مبلغ**: هش تراکنش + آدرس → مسیر پول، مقصدهای نهایی، درصد اطمینان هر مرحله
- **ارتباط کیف‌ها**: لیستی از آدرس‌ها (۲ تا ۵۰) را بچسبانید → کدام کیف‌ها مستقیم به هم پول داده‌اند (مثلاً «۳٬۹۹۹ USDT از #۳ به #۷» با هش تراکنش)،
  کدام از طریق یک کیف واسط (با تشخیص «همان پول» وقتی مبلغی مشابه کمی بعد از واسط خارج شده)، طرف‌حساب‌های مشترک، گروه‌های مرتبط، گراف و خروجی CSV/JSON
- **پرونده‌ها**: جمع کردن آدرس‌ها، ردیابی‌ها و یادداشت‌های یک تحقیق؛ گزارش HTML/PDF و خروجی JSON
- **واچ‌لیست**: هشدار تراکنش جدید (با حداقل مبلغ و توکن)
- **برچسب‌ها**: لیست صرافی‌ها، میکسرها و **بیش از ۱۰۰۰ آدرس تحریم‌شده‌ی OFAC**، و برچسب‌های خودتان

### ارزش دلاری و تومانی
کنار هر مبلغ (تراکنش‌ها، طرف‌حساب‌ها، موجودی، ردیابی، ارتباط کیف‌ها، هشدارها، گزارش‌ها، CSV و ربات) ارزش آن به **دلار و تومان** نمایش داده می‌شود.
واحد نمایش از نوار بالا انتخاب می‌شود: «دلار + تومان»، «تومان»، «دلار» یا «فقط توکن».
- برای هر تراکنش، ارزش **در روز همان تراکنش** نمایش داده می‌شود و با نگه داشتن ماوس روی آن، ارزش **امروز** هم دیده می‌شود.
- نرخ تومان: قیمت USDT/تومان نوبیتکس (برای روزهای گذشته، کندل‌های روزانه‌ی نوبیتکس)؛ اگر در دسترس نبود والکس، و اگر هیچ‌کدام نبود نرخ دستی صفحه‌ی تنظیمات.
- قیمت دلاری: استیبل‌کوین‌ها = ۱ دلار؛ بقیه از CoinGecko (یک سال اخیر) و Binance (قدیمی‌تر). توکن‌های جعلی و ناشناخته ارزش ندارند.
- نرخ‌های روزانه در پایگاه داده ذخیره می‌شوند و هر روز فقط یک‌بار دانلود می‌شود.

فارسی/انگلیسی و تم روشن/تیره از نوار بالا عوض می‌شوند. روی گوشی هم کار می‌کند.

## روش ردیابی (برای گزارش پروژه)

### گراف چندلایه
از ولت شروع و به‌صورت BFS لایه به لایه جلو می‌رود؛ از هر ولت فقط `max_children` طرف‌حساب بزرگ‌تر نگه داشته می‌شود.
با گزینه‌ی **ترتیب زمانی**، از هر ولت فقط انتقال‌هایی دنبال می‌شوند که **بعد** از رسیدن پول به آن ولت انجام شده‌اند
(و در جهت عکس، قبل از خروج). ولت‌های پرتراکنش و آدرس‌های برچسب‌خورده به‌عنوان صرافی/بریج/میکسر باز نمی‌شوند،
چون پول کاربران مختلف در آن‌ها با هم ترکیب می‌شود.

### ردیابی یک مبلغ
داخل یک ولت پول‌ها قابل تفکیک نیستند؛ پس تخصیص مدل‌سازی می‌شود:

1. **تطبیق دقیق** — اگر کمی بعد از دریافت (پیش‌فرض ۷۲ ساعت) تقریباً همان مبلغ (±`tolerance`) خارج شده، همان
   انتقال حامل پول در نظر گرفته می‌شود. اطمینان: ۹۵٪.
2. **حسابداری لات (lot)** — بقیه‌ی دریافتی‌ها «لات» هستند و هر خروجی به ترتیب **FIFO** (اول قدیمی‌ترین پول) یا
   **LIFO** (اول جدیدترین پول) از آن‌ها خرج می‌کند. اطمینان: ۷۰٪.

اطمینان در طول مسیر ضرب می‌شود؛ شاخه‌هایی که دوباره به هم می‌رسند ادغام می‌شوند. ردیابی رو به عقب («این پول از کجا آمد؟»)
همان تخصیص را برعکس می‌خواند. پایان هر شاخه یکی از این‌هاست: رسید به صرافی/سرویس، مانده در ولت، ولت پرتراکنش،
منبع نامشخص، سقف مراحل، خردشدن زیر حداقل، حلقه.

### ارتباط بین چند کیف پول
تاریخچه‌ی همه‌ی کیف‌های لیست (با فیلتر توکن، پیش‌فرض USDT، و حذف توکن‌های جعلی) گرفته می‌شود و بدون دانلود اضافه:
1. **انتقال مستقیم** — انتقال‌هایی که فرستنده و گیرنده‌شان هر دو در لیست‌اند.
2. **انتقال از طریق واسط** — A → C → B که C خارج از لیست است و پول از C **بعد** از رسیدن خارج شده. هر ورودی با اولین خروجی
   هم‌مبلغ (±۳٪) در بازه‌ی ۷۲ ساعت جفت می‌شود («همان پول»). مسیر از طریق صرافی/سرویس‌ها نگه داشته ولی «شواهد ضعیف» علامت می‌خورد.
3. **طرف‌حساب مشترک** — کیفی که به چند عضو لیست پول داده (منبع مشترک) یا از چند عضو گرفته (مقصد مشترک).
4. **گروه‌ها** — اعضایی که با انتقال مستقیم یا از طریق واسط (غیر صرافی) به هم وصل‌اند (union-find).

با **جستجوی عمیق**، تاریخچه‌ی ۲۵ کیف واسط اصلی هم گرفته می‌شود تا مسیرهای سه‌مرحله‌ای A → C → D → B پیدا شوند (ولت‌های پرتراکنش دنبال نمی‌شوند).

### امتیاز ریسک (۰ تا ۱۰۰)
جمع امتیاز یافته‌ها (سقف ۱۰۰). هر یافته شواهدش را همراه دارد:

| یافته | معیار |
|---|---|
| آدرس برچسب‌خورده | خود آدرس تحریم/میکسر/کلاهبرداری است (۱۰۰) |
| تماس مستقیم | تراکنش با آدرس تحریمی/میکسر/کلاهبرداری (۳۰–۴۰) |
| تماس غیرمستقیم | همین آدرس‌ها در فاصله‌ی ۲ لایه (بررسی عمیق، ۱۵) |
| ولت عبوری | خروجی ≈ ورودی (۹۰–۱۱۰٪) و میانه‌ی زمان نگهداری زیر ۲۴ ساعت (۲۰) |
| جابه‌جایی سریع | میانه‌ی زمان نگهداری زیر ۱ ساعت (۱۵) |
| واسط کوتاه‌عمر | عمر زیر ۷ روز، حداکثر ۱۲ انتقال، خالی‌شده (۱۵) |
| Fan-in / Fan-out | ≥۱۰ فرستنده یا گیرنده‌ی مختلف در ۲۴ ساعت (۱۰) |
| Structuring | ≥۳ انتقال استیبل‌کوین بین ۹٬۰۰۰ و ۹٬۹۹۹ (۱۰) |
| مبالغ رُند | ≥۵۰٪ خروجی‌ها مضرب ۱۰۰ (۵) |
| ولت جدید پرحجم | عمر زیر ۳۰ روز و بیش از ۱۰۰٬۰۰۰ استیبل‌کوین (۱۰) |
| فعال‌شدن دوباره | بیش از ۱۸۰ روز بی‌فعالیت (۵) |
| Address poisoning | دریافت dust از آدرس‌های هم‌شکل طرف‌حساب‌ها؛ و اگر به آن‌ها پول فرستاده: «احتمال از دست دادن پول» |

زمان نگهداری با همان تخصیص FIFO محاسبه می‌شود. توکن‌های تقلبی (نماد USDT با قرارداد دیگر) و انتقال‌های صفر به‌عنوان
اسپم کنار گذاشته می‌شوند.

### بیت‌کوین
هر تراکنش UTXO به یال‌های آدرس‌به‌آدرس تبدیل می‌شود: ارسال به همه‌ی خروجی‌ها به‌جز آدرس‌های ورودی (باقی‌مانده/change)،
و در ورودی‌های چندآدرسی به نسبت سهم هر آدرس تقسیم می‌شود.

## ربات تلگرام

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام دهید، `/newbot` و توکن را در `TELEGRAM_BOT_TOKEN` بگذارید.
2. برنامه را اجرا کنید و به ربات `/start` بدهید؛ شناسه‌ی شما را می‌گوید. آن را در `TELEGRAM_ALLOWED_USERS` بگذارید (چند شناسه با کاما) و دوباره اجرا کنید.

دستورها: فرستادن یک آدرس (یا `/wallet`)، `/graph`، `/risk`، `/trace <آدرس> <هش> [مبلغ] [back]`، `/watch <آدرس> [حداقل] [توکن]`، `/unwatch`، `/watchlist`، `/links <آدرس۱> <آدرس۲> ...`.
اگر لیستی از چند آدرس را یک‌جا بفرستید، ربات خودش ارتباط بین آن‌ها را بررسی می‌کند.
هشدارهای واچ‌لیست به همان چت ارسال می‌شوند.

## اتصال به Claude (MCP)

`python mcp_server.py` یک سرور MCP (stdio) با ابزارهای `wallet_overview`, `counterparties`, `transfers`,
`fund_flow_graph`, `trace_funds`, `risk_report`, `wallet_links`, `money_value`, `label_address`, `get_label`, `detect_address` است.
در Claude Desktop، محتوای `claude_desktop_config.example.json` را (با مسیر درست) به تنظیمات اضافه کنید.

## API

مستندات تعاملی: <http://127.0.0.1:8765/docs>

| Endpoint | توضیح |
|---|---|
| `GET /api/detect/{address}` · `GET /api/wallet/{a}/activity` | تشخیص شبکه / شبکه‌های دارای فعالیت |
| `GET /api/wallet/{a}/overview` | موجودی، ارزش دلاری، جمع ورودی/خروجی |
| `GET /api/wallet/{a}/counterparties` · `/transfers` (+ `.csv`) | طرف‌حساب‌ها / انتقال‌ها با فیلتر |
| `GET /api/wallet/{a}/timeline` · `/risk` · `/report` | نمودار زمانی / ریسک / گزارش HTML |
| `GET /api/graph/{a}` · `/api/graph/{a}/image.png` | گراف چندلایه / تصویر |
| `POST /api/trace` | ردیابی مبلغ |
| `POST /api/links` → `GET /api/links/{job}` | ارتباط بین چند کیف (در پس‌زمینه، با درصد پیشرفت) |
| `GET /api/prices/rates` · `POST /api/prices/quotes` | نرخ دلار به تومان / قیمت دلاری و نرخ تومان هر توکن در یک روز |
| `/api/labels`, `/api/cases`, `/api/watchlist`, `/api/alerts` | برچسب‌ها، پرونده‌ها، واچ‌لیست، هشدارها |

فیلترها: `token`, `direction`, `min_amount`, `max_amount`, `start`, `end`, `counterparty`, `include_failed`, `hide_spam`.

## توسعه

```bash
pip install -r requirements-dev.txt

cd frontend && npm install
npm run dev                      # داشبورد روی :5173 با اتصال به API روی :8765
```

به‌روزرسانی لیست تحریم‌ها: `python scripts/update_sanctions.py`

## محدودیت‌ها

- ردیابی مبلغ و امتیاز ریسک **مدل‌محور و احتمالاتی** هستند، نه قطعی؛ همیشه با داده‌ی بلاکچین بررسی شوند.
- تبدیل توکن‌ها (swap) و عبور از بریج بین شبکه‌ها دنبال نمی‌شود؛ ردیابی روی همان توکن ادامه دارد.
- APIهای رایگان سقف درخواست دارند؛ ولت‌های خیلی پرتراکنش فقط تا `MAX_TRANSFERS_PER_ADDRESS` بررسی می‌شوند.
- برچسب صرافی‌ها محدود است (چند صرافی بزرگ). برچسب‌های ترونِ مشخص‌شده با «likely/verify» از حافظه هستند و باید روی tronscan تأیید شوند؛ برچسب‌های خودتان را اضافه کنید.
